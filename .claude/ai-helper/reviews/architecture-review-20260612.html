1 · Give the Ability-atom vocabulary an interface

Strong in-process

systems/AbilitySystem.gd:103–202 · data/AbilityData.gd (120 Abilities) · test/unit/data/test_ability_data.gd

Before — interface is the match statement
AbilityData — 120 entries author atoms
must somehow know: 10 kinds · required fields per kind · default target (opponent for apply_status, own for add_max_hp) · which kinds scale by potency
↓
_apply_atom — 99-line match
typo'd kind / missing field → falls through → return {} — silent no-op in combat
test_ability_data.gd
validates triggers, targets, int-ness — never validates a single atom kind or its fields
After — one registry, three readers
ATOM_SCHEMAS (const, beside the match)
"prime_dot": { required: [status, amount], default_target: "opponent", potency_aware: true }
_apply_atom
reads default target
data test
locks all 120 × effects
future authoring
the written contract

Problem: the atom set is a shallow seam — every fact an Ability author needs lives only inside the implementation, and a bad atom is a silent no-op.

Solution: a const atom-schema registry; the match and a new data test both read it.

  • Locality: atom facts in one const
  • Leverage: one test locks 120 entries
  • Typos fail red, not silent
  • Potency-awareness becomes written, checkable

Problem: 120 hand-written description literals went stale the day potency became tier-scaled — already on the UI backlog, but as text fixes it will rot again at the next knob change.

Solution: template the amounts and render every description through one describe(id, level) interface.

  • Leverage: one renderer, three surfaces
  • Descriptions track future knob changes

Speculative: design may prefer showing base amount + a tier multiplier badge instead — settle that first.

Top recommendation

#1 — Atom-schema registry. The current sprint is content churn on 120 Ability entries, and every new entry is one typo from a silent combat no-op. A const registry + one data test is an afternoon, locks the whole data file, and makes #4 (status-modifier schema) a natural follow-up in the same shape. Honourable mention: #3 ships with a real bug fix (grown boards lose Battle Summary rows).
