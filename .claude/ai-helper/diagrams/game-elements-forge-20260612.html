⑥ Status & ability mechanics — how each one works

The functional behaviour pulled from StatusSystem.gd. Status is a flat per-side pool shared by every element on that side; potency = the applying element's Level (a Lv-N element applies N stacks). Magnitudes are mostly ×1 placeholders for the balance pass.

StatusTypeMagnitudeHow it actually works
🔥 BurnDOTstacks × 1 dmg / tick (+bonus)Ramping DOT. −1 stack each 1s tick. Armor absorbs it at HALF rate (raw/2), never below armor floor. Steel's plating can also shave it. A DOT tick is a 'damaging event' → consumes a curse charge.
🧪 PoisonDOTstacks × 1 dmg / tick (+bonus)Permanent DOT — stacks NEVER decrement. Armor does NOT soak poison at all (only plating-reduces_dot can). Underrot adds +1/tick. The slow-burn win condition.

Trigger vocabulary

combat_startfires once at t=0 — reserved for TRUE setup since the 2026-06-12 rebalance: walls (boulder/brick), freezes (glacier/iceage), deep curse (void/voidrift), max-HP bulk (ironwood/ancientgrove).
periodicfirst fire at +interval, then every interval. Capped at 3 iconic engines (lava, volcano, rainbow) — the element's own cooldown already provides "every X seconds", so on_activate carries that rhythm now.
passivequeried at the calc site — modifies a rule for the whole combat (Blaze burn+1, Plasma shock+3, Acid armor-no-regen, Tempest cleanse-proof shock) or carries an adjacency aura (Root/Obsidian/Primordial).
passive_on_hit% roll on every damage hit (seeded RNG) — Dust/Static/Flint/Pollen/Sand/Haze sprinkle a status.
on_activateeach fire (optional every_n gate, optional multicast) — the workhorse trigger post-rebalance: rides the element's own cooldown. Build-up payoffs (Tsunami every 4th, Supernova every 3rd) create timing decisions.
on_* reactivedepth-1 reaction to an event: on_burn_applied, on_heal_applied, on_leech, on_damage_dealt, on_poison_tick, on_burn_tick, on_armor_stripped, on_haste_applied, on_status_applied. The synergy chains — now ~1/3 of the roster.

Multicast (×2 at T2/T3, ×3 at T4) repeats the whole fire, each repeat an independent reactive trigger. Reactives never re-trigger reactives (depth-1).
