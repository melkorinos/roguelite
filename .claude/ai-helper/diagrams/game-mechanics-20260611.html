T1 is always available (~70%/slot) so the forge engine is never starved.

Merge (level axis)

Two of the same element at the same Level → one at Level+1. Drag-drop, no recipe, no gold. Buying onto a matching Lv1 also merges → Lv2.

Result lands in min(slot_a, slot_b); other slot cleared.

Forge (tier axis · ADR 0008)

Recipe A+B→C, one Tier up. Both inputs Level ≥ 2. Result Level = max(1, min(inputs) − 1) → two Lv2s give a Lv1 of the next tier.

Outcomes: ok · no_recipe · level_too_low · inv_full · no_gold. level_too_low keeps items staged (you can Merge them up).

Sell

Drag to SellZone → refund price / 2. Works from inventory or grid. No level scaling on refund — a Lv3 refunds the same as a Lv1.

⚠ Possible balance leak: merging then selling loses value; selling never recoups merge/forge investment.

Two progression gates fed by Forge

Tier unlock (ADR 0007)

Forging distinct results writes run_discoveries. Unlock thresholds: T2 = 3 · T3 = 2 · T4 = 1 distinct forges. Once unlocked, the full pool for that tier is available (family-filter removed 2026-06-12, ADR 0015 — roster at 105 is small enough to not need it). Slot mix still skews toward ingredient variety via _pick_spread. A granted element (Event reward) never writes run_discoveries — forging is the only unlock path.

Grid Growth (ADR 0014)

Owning (inv/grid/bench) an element at a milestone grants +1 Battle Slot, once per run, path-agnostic: T2 Lv2 → 5th slot, T3 Lv2 → 6th slot. Base 4, hard cap 8. Checked via ForgeSystem.apply_grid_growth after every merge/forge/drop (idempotent).

Effective cooldown = base × 0.7 (global mult) + side cd_modifier, then ×(1+shock slow), round, floor 10 dc (1/sec).

Sandstorm (ADR 0012) — at t=30s, true damage hits both sides each storm-second: 5 + 5·k (k from 0). Bypasses all mitigation by design. Guarantees every fight ends in a KO; hard cap 60s is only a determinism backstop. No HP-comparison timeout exists — a fight is won only when the opponent reaches 0 HP.

③ Damage pipeline — the bug-hunt surface

This is where damage-calc and interaction bugs live. Two distinct paths feed HP: a direct hit (only ~20% of T2+ elements, the DAMAGE_DEALERS) and a DOT tick (burn/poison, once per second). They apply mitigation in different orders — a common source of confusion.

Asymmetries worth verifying during the bug hunt

  • Curse is consumed twice over. Both the direct-hit path and each DOT tick consume a curse stack and add the amplifier. A single curse stack can be spent by whichever damaging event lands first in a tick — confirm that's intended ordering (status tick runs before _tick_side fires within the same tick_battle call).
  • Armor treats burn (½ rate) and direct/poison differently. Burn is soaked at half rate and never below armor.floor; poison is not soaked by armor at all; plating only touches DOT when reduces_dot is set.
  • Pure-effect elements skip the entire damage block (raw==0) — no armor-strip event, no curse consumption. All T1 + most T2+ are pure-effect, so most "damage" is actually DOT laid by statuses.
  • Multicast repeats the full fire N× — each repeat an independent event/reactive. Caps: 2× at T2/T3, 3× at T4.
  • Weaken only reduces direct hits, not DOT ticks (it lives on the attacker, DOT has no live attacker at tick time).

⑥ Things to watch in the balance/bug pass

  1. Opponent HP is board-independent. compute_opponent_hp keys off round only (100 × growth), ignoring the opponent's actual board. A grown opponent board deals more but absorbs the same — verify offence/defence don't decouple unfairly.
  2. Sandstorm dominates long fights. Anything not resolved by ~30s gets pulled to a KO by escalating true damage on both sides — defensive/DOT builds racing the clock can flip to a coin-toss. Check how often fights actually reach the storm.
  3. Curse double-consumption across the hit path and DOT path within one tick (status tick runs first). Confirm the spend order is intended.
  4. Sell refund ignores level. Merge/forge value is unrecoverable on sell — intended sink or leak?
  5. Most elements deal 0 direct damage. Real damage is DOT laid by statuses; effective_damage > 0 only for ~20% of T2+. The "damage" knobs (base × multiplier × level) affect a small minority.
  6. Status magnitudes are ×1 placeholders. Burn/poison/armor/etc. are deliberately flat — the per-stack values are the primary balance levers and currently undifferentiated.
  7. Determinism is the test asset. Same boards + hash("combat:%d" % round) seed = identical fight. Lean on simulate_battle for regression checks on any damage-calc change.
